### Integrity and Verification

SHA-256 is used to identify the exact byte sequence of each archived artifact. Independent verification can be performed by computing the SHA-256 digest of a local copy and comparing it with the corresponding value in the Artifact Register.

A matching digest establishes that the file being examined is byte-for-byte identical to the version represented by this public record. A nonmatching digest indicates that the file differs from the archived version and should be treated as a separate artifact or revision.

### Evidentiary Boundary

This repository functions as a public provenance and integrity record. Cryptographic hashes and Git commit timestamps can support documentation of file integrity and the existence of a particular public record at a particular point in repository history. They do not, independently, establish originality, priority of authorship, empirical validity, institutional approval, regulatory compliance, intellectual-property ownership, or legal entitlement.

Those questions require their own evidence and applicable evaluative or legal processes.

### Provenance Chain

`Artifact → Canonical Version → SHA-256 → Evidence Record → Archive → Public Commit`

This chain is intended to preserve a reproducible relationship between substantive work products and their public integrity records without overstating what cryptographic provenance can establish.
